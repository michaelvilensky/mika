# 🧁 המאפיה של מיקה — מסמך תכנון

מסמך זה מתאר את עיצוב המשחק. שינויים עתידיים — לעדכן את המסמך לפני/אחרי שינוי הקוד.

## קהל יעד
- ילדה בת 7 שמתקשה עם חיבור
- צריך להיות **כיפי, מרגש, אבל לא קשה מדי ולא משעמם**

## מטרה לימודית
- חיבור מספרים דו-ספרתיים **בלי המעבר של 1 לעשרות**
- כלומר: סכום האחדות ≤ 9, סכום כללי ≤ 99
- חיזוק הבנת **ערך מקום** (עשרות + אחדות) ע"י ייצוג ויזואלי

## רעיון מרכזי
הילדה מנהלת מאפיה. לקוחות (חיות חמודות) נכנסים ומבקשים הזמנות של **מגוון מאפים** (עוגיות, קאפקייקס, דונאטס, קרואסונים, עוגות, בייגלה).
ההזמנה מוצגת **ויזואלית** (מגשים של 10 + בודדים) ו**נאמרת בקול** ע"י החיה (TTS).
הילדה בוחרת תשובה נכונה ומקבלת מטבעות שאפשר לקנות בהם קישוטים שהיא מציבה (גוררת) בכל מקום במסך.

## סוגי מאפים
כל שאלה משתמשת בסוג מאפה אקראי. הסוג משפיע רק על אימוג'י המאפים בתצוגה ועל הטקסט של הלקוח — המתמטיקה זהה.
- 🍪 עוגיות
- 🧁 קאפקייקס
- 🍩 דונאטס
- 🥐 קרואסונים
- 🍰 עוגות
- 🥨 בייגלה

## מבנה המשחק

### זרימה
1. **מסך פתיחה** — "ברוכים הבאים למאפיה של מיקה!" + כפתור התחלה
2. **לולאה מרכזית**:
   - לקוח אקראי נכנס + שם + בועת דיבור עם ההזמנה
   - הצגה ויזואלית של שני המספרים (מגשים + בודדות)
   - 3 כפתורי תשובה (אחד נכון, שניים מטעים מסתבר)
   - בחירה → משוב מיידי (אנימציה + סאונד)
   - כל הצלחה = +1 מטבע
   - כל 5 הצלחות ברצף = בונוס + מיני-חגיגה
3. **חנות הקישוטים** — אפשר להוציא מטבעות על קישוטים לחנות (לבחירה מהמסך הראשי)

### רמות (התקדמות הדרגתית)
| רמה | תיאור | דוגמה | מס׳ שאלות |
|------|--------|--------|------------|
| 1 — חימום | אחדות + אחדות | 3 + 4 | 3 |
| 2 — עשרות עגולות | עשרת + עשרת | 20 + 30 | 4 |
| 3 — שילוב | עשרות + אחדות | 23 + 14 | 8+ (ממשיך) |

**מעבר בין רמות**: בראש מסך המשחק יש "פילים" (pills) — אחת לכל רמה. הילדה יכולה ללחוץ עליהן כדי לעבור לרמה אחרת **באמצע משחק**. מטבעות ורצף נשמרים — רק התרגיל מתחלף.

החוקים למחולל השאלות (חייב לעמוד תמיד):
- `a + b ≤ 99`
- `(a % 10) + (b % 10) ≤ 9` (בלי מעבר עשרת)
- שני המספרים > 0
- אין חזרה על אותה שאלה פעמיים ברצף

### יצירת תשובות מטעות
- אחד נכון
- אחד "טעות נפוצה" — החלפת ספרות/עשרות, או נכון ±10
- אחד אקראי בטווח סביר (±1 עד ±20)
- כולן בטווח 1–99, לא שליליות

## מערכת רמזים (חינוכית)

הילדה לא צריכה להרגיש שהיא "נכשלת". הרמזים עוזרים לה להגיע לתשובה לבד.

- **אחרי 5 שניות בלי תשובה** או **אחרי טעות ראשונה**:
  > 💡 "בואי נספור את המגשים השלמים קודם: X + Y מגשים = ?"
- **אחרי טעות שנייה**:
  > 💡 "X עשרות + Y אחדות = התשובה"
  + הדגשת המגשים והאחדות נפרד עם תוויות
- **אין "טעית!"** — רק עידוד: "כמעט! בואי ננסה שוב 💛"

## עיצוב ויזואלי

### פלטת צבעים
- רקע: gradient חם (קרם → אפרסק)
- מגש: חום עץ עם מסגרת
- עוגיות: גוון שקד עם נקודות שוקולד
- כפתורים: ורוד פסטל / טורקיז רך
- מטבעות: זהב מבריק

### גופן
- Heebo / Varela Round / Rubik — ידידותי, מעוגל, קריא בעברית

### פריסה
- RTL
- כפתורים גדולים (touch-friendly לטאבלט)
- אנימציות עדינות, לא מסיחות

### דמויות (לקוחות)
אימוג'ים — מעורבב מהרשימה:
🐰 ארנבי, 🐻 דובי, 🦊 שועלי, 🐱 חתולי, 🐶 כלבלב,
🦁 אריה, 🐼 פנדה, 🐨 קואלי, 🐸 צפרדע, 🦄 חד-קרן,
🐲 דרקון, 🦉 ינשוף, 🐧 פינגווין, 🦒 ג׳ירף, 🐮 פרה, 🐷 חזרזיר

### דיבור (TTS)
- כל לקוח **אומר את התרגיל בקול** בעברית כשמופיע: `"אני רוצה X ועוד Y [מאפה]"`
- **לכל חיה קול ייחודי** — שילוב של `pitch` (0.3–1.9) ו-`rate` (0.8–1.2)
  - חיות גדולות (אריה, דרקון, פרה) — קול נמוך ואיטי
  - חיות קטנות (ארנבי, חזרזיר, חד-קרן) — קול גבוה ומהיר
- **לחיצה על החיה** מפעילה את הדיבור שוב (לצורך תרגול שמיעה)
- משתמש ב-`speechSynthesis` של הדפדפן עם קול עברית (`he-IL`)
- כפתור 🔊/🔇 מכבה גם דיבור וגם צלילים
- **אם אין קול עברית** מותקן בדפדפן — **משתיקים TTS לחלוטין** במקום לדבר באנגלית (היה באג של הקראה באנגלית)
- גילוי קול עברית: בודק `he-IL`, `he`, `he-*`, `iw` (קוד ISO ישן), וגם לפי שם הקול (Carmit, Hebrew)
- ממתינים ל-`voiceschanged` event לפני דיבור ראשון (Chrome טוען קולות אסינכרונית)

## תגמולים והתקדמות

### מטבעות
- כל תשובה נכונה: +1 מטבע
- בונוס רצף (3 ברצף): +2 מטבעות נוספים
- בונוס רצף (5 ברצף): +5 מטבעות + הודעת חגיגה

### קישוטים (חנות)
| פריט | מחיר |
|------|------|
| 🌸 פרח | 5 |
| 🎈 בלון | 8 |
| ⭐ כוכב | 10 |
| 🧸 דובי | 15 |
| 🎂 עוגה | 20 |
| 👑 כתר | 25 |
| 🌈 קשת | 35 |
| 🦄 חד-קרן | 50 |

**מאפיינים:**
- אפשר לקנות את **אותו הקישוט מספר פעמים** (כל קנייה = מופע חדש)
- כל מופע מוצג **גדול** (כ-5rem) ו**ניתן לגרירה** לכל מקום במסך
- מיקום כל מופע נשמר כיחס (x, y בין 0-1 ביחס לחלון) → עמיד לשינוי גודל מסך
- **מחיקה**: בזמן גרירה, מופיע אזור פח 🗑️ בתחתית — שחרור מעליו מוחק
- כל המידע נשמר ב-`localStorage` (מטבעות + מערך מופעים)

**שכבה ויזואלית:**
- כל הקישוטים על שכבת `position: fixed` עליונה
- השכבה עצמה `pointer-events: none` — לא חוסמת אינטראקציה עם המשחק
- כל קישוט בעצמו `pointer-events: auto` — נגיש לגרירה
- כלומר: קישוט שמוצב מעל כפתור לא חוסם לחיצה על כפתור סביבו, אבל הוא עצמו ניתן לגרירה

### שמירת נתונים
- `localStorage` שומר: מטבעות, קישוטים שנקנו, רצף שיא, מס׳ תשובות נכונות מצטבר

## פרופילים (V4 - Layer 1)
**מטרה**: כמה ילדים/בני משפחה יכולים לשחק על אותו מכשיר עם שמירות נפרדות.

**זרימה:**
1. בכניסה ראשונה למשחק (וכל פעם שאין פרופיל פעיל): מסך **בחירת שחקן**
2. ילדה בוחרת פרופיל קיים → נטען המצב שלה
3. או לוחצת "**+ הוסיפי שחקן**" → טופס: שם + אווטר → נוצר פרופיל חדש עם sync code
4. במסך הראשי: שם השחקן ואווטר בכותרת
5. כפתור "**החליפי שחקן**" → חוזר לבחירה

**מבנה נתונים** (`localStorage`):
- `mika-bakery:profiles` — מערך IDs של כל הפרופילים, לפי סדר יצירה
- `mika-bakery:active-profile` — ID של הפרופיל הנוכחי
- `mika-bakery:profile:{id}` — אובייקט פרופיל מלא:
  ```json
  {
    "id": "abc123",
    "name": "מיקה",
    "avatar": "🦄",
    "syncCode": "K7M-9PQ",
    "createdAt": 1717900000000,
    "save": { "coins": 12, "decorations": [...], "bestStreak": 5, ... }
  }
  ```

**Sync code** (לעתיד ב-Layer 2):
- 6 תווים, פורמט `XXX-XXX`
- מתוך אלפבית ללא תווים מבלבלים: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (אין 0/O/1/I/L)
- ייחודי לפרופיל. ישמש בעתיד לסנכרון בין מכשירים.

**מיגרציה**:
- אם קיים מפתח ישן `mika-bakery-save-v1` ואין פרופילים — נוצר פרופיל ברירת מחדל בשם "מיקה" עם הנתונים הישנים.
- המפתח הישן לא נמחק (לבטיחות).
